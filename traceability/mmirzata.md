# Traceability: mmirzata (Madina Mirzatayeva, team 2HDMI)

**Feature:** AI involvement summary. A grader-readable list of the files and line ranges OpenCode changed in a session (`opencode session involvement <sessionID>`).

**Code under test:**

- `packages/opencode/src/session/involvement.ts`: turns a session's file diffs into report rows (file, status, +/- counts, line ranges) and formats the report
- `packages/opencode/src/cli/cmd/session.ts`: the `session involvement` CLI command

**Property tests:** `packages/opencode/test/session/involvement.property.test.ts`

Interview evidence IDs (C-_n_ classmate, S-_n_ course staff, O-_n_ outside interviewee) refer to the notes in my Project 4A workbook.

## Requirements at a glance

- **R1 (No invented files):** the report only lists files the session actually recorded changes for.
- **R2 (Exact changed lines):** each file shows its path, status (added / modified / deleted), and the line ranges that changed.
- **R3 (Deleted files stay listed):** a file the AI added stays in the report even after it is deleted from disk.
- **R4 (Trailing blank line is harmless):** an extra blank line at the end of a file does not change how the real edit is reported.
- **R5 (Counts match git diff):** the + / - line counts per file equal what `git diff --numstat` reports.
- **R6 (Clear errors, no crashes):** a missing or empty session gives a short message, never a stack trace.
- **R7 (Show the prompt behind each change):** each file lists the user prompt(s) that led to it (deferred).

## Requirement changes

| ID  | Original (P4A)                                                                                                                                       | Revised (P4B)                                                                                                                                                                                                 | Why it changed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **R1: No invented files** | The report lists only files that the AI changed in that session. It never lists a file that only the student edited.                               | The report lists exactly the files in the session's recorded diffs, each file once. It never lists a file that is not in the session's recorded changes.                                                       | **Not feasible as stated.** OpenCode records a session's changes by snapshotting the whole working tree at turn boundaries (`src/snapshot/index.ts`). If the student edits a file by hand while a session is running, that edit is in the snapshot too, and nothing in the recorded data says who made it. So the report cannot promise "never a student-only file". What the interviewees actually needed (C-3, S-8: don't wrongly accuse the student; O-5: don't invent files) is that the report never claims more than the session recorded. The revised wording keeps that and drops the part that cannot be known. |
| **R3: Deleted files stay listed** | A file the AI added still appears in the report after the student deletes it from disk, and deleting one file does not change the other files in the report. | A file the AI added in a session stays in that session's report even if it is later deleted from disk, and the entry for one file never depends on the other files in the report.                              | **Partly not feasible.** S-9 and O-7 also wanted the report to say the *student* deleted the file. The report is built from the diffs stored for the session, not from the disk, so a deletion the student makes outside the session is never recorded and cannot be shown. The part users relied on (S-10, S-11: "I still want to see it") is feasible and kept. "Deleting one file does not change the others" is restated as a checkable rule: one file's entry never depends on the other files.                                                                 |
| **R4: Trailing blank line is harmless** | An extra blank line at the end of a file does not change that file's name, status or changed line ranges in the report.                            | An extra blank line at the end of a file does not change that file's name, status, or the line ranges of the real edit. The blank line itself may still be reported.                                           | **Conflict between interviewees.** S-12 and C-9/C-10 wanted the blank line ignored, but O-10/O-11 said any change, even a blank line, is worth knowing about ("why is it doing it? Maybe there's a mistake in the model"). The revision satisfies both: the real edit is reported exactly the same way (what S-12 and C-9 cared about), and the blank line can still appear as one small extra range and +1 (what O-10 asked for). Hiding a real added line would also make the + count disagree with git diff (R5).                                                            |
| **R6: Clear errors, no crashes** | ... Running it on a session with no file changes prints a "no changes" message and exits with code 0.                                              | ... Running it on a session with no file changes prints the header with `0 files, +0 / -0` and exits with code 0.                                                                                             | **Checkability.** "A 'no changes' message" did not say what text counts, so it could not be checked. The interviewee's concern (C-4) was crashing or showing a stack trace on an empty session, not specific wording. The revised criteria name the exact output the command already prints, so the rule can be checked. The "session not found" part is unchanged.                                                                                                                                                                                                       |
| **R7: Show the prompt behind each change** | (New) For each changed file, the report shows the user prompt that led to that change.                                                              | (New, deferred) For each changed file, the report lists the user prompt or prompts whose turns changed that file.                                                                                           | **Not feasible as stated, and out of scope for 4B.** One file can be changed by several prompts, so "the prompt" is ambiguous. The current command also merges all of a session's diffs by file name, keeping only the last diff for each file, so it does not track which prompt produced which file. The revised wording handles several prompts. It is deferred: it needs new code to keep the prompt next to each per-turn diff, so I am not writing a property for it in this project.                                                                                             |

R2 and R5 are kept as written. Both describe behavior the code is supposed to provide from the recorded diffs, and both can be checked automatically. R2 against the lines that were actually edited, R5 against `git diff --numstat`.
